## 1. Executive Summary

This report documents the architectural transition of the **Cross-Repo Dependency Impact Mapper** and **CodeCity Metropolis** platform from local single-tenant MySQL 8 to **Neon Serverless PostgreSQL**. The migration satisfies the non-negotiable requirements of preserving 100% of existing repository analysis, 2D metropolis spatial layouts, AST parsers, API journey playback, and dependency graph algorithms while establishing a production-ready, horizontally scalable, multi-tenant database tier.

## 2. Schema Type Mapping & Dialect Adaptations

Every column definition was audited and ported to standard PostgreSQL DDL:

| MySQL 8 Construct | Neon PostgreSQL Target | Impacted Tables | Architectural Reason |
|:---|:---|:---|:---|
| `BIGINT AUTO_INCREMENT PRIMARY KEY` | `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | All 11 tables (`repositories`, `architecture_snapshots`, `architecture_nodes`, `architecture_edges`, `repo_dependencies`, `city_layouts`, `code_endpoints`, `static_execution_paths`, `runtime_traces`, etc.) | SQL:2008 standard identity columns; native sequence generation without MySQL-specific auto-increment locks. |
| `LONGTEXT` | `TEXT` | `city_layouts` (`layout_json`, `districts_json`, `buildings_json`) | PostgreSQL `TEXT` supports up to 1GB per value with automatic TOAST storage compression. `CityLayout.java` JPA entity was updated from `columnDefinition = "LONGTEXT"` to `columnDefinition = "TEXT"`. |
| `TINYINT(1)` | `BOOLEAN` | `repositories.is_monorepo`, `code_endpoints.has_journey`, `code_endpoints.runtime_verified` | PostgreSQL has native `BOOLEAN` type with true boolean evaluation rather than integer coercion. |
| `DATETIME(6)` | `TIMESTAMP` | `created_at`, `analyzed_at`, `added_at`, `indexed_at` | Native microsecond timestamp representation. |
| `VARCHAR(255)` / `TEXT` | `TEXT` / `VARCHAR` | Node identifiers, method signatures, package paths | Preserved length boundaries while ensuring unicode UTF-8 compliance. |
| `UUID` | `UUID` | `app_users.id`, `app_users.supabase_user_id`, `repositories.owner_id` | Native 128-bit RFC 4122 binary representation with indexed lookups. |

## 3. Flyway Versioned Migration Scripts

Schema creation and version evolution are managed strictly by **Flyway 9.22.3** (`flyway-core`):

### 3.1 Migration `V1__initial_postgresql_schema.sql`
- Reconstructs all 11 core tables of the platform with standard PostgreSQL DDL.
- Adds foreign keys with `ON DELETE CASCADE` from `architecture_snapshots` to `architecture_nodes`, `architecture_edges`, and `city_layouts`.
- Creates 14 performance indexes covering:
  - `idx_repo_name` on `repositories(repo_name)`
  - `idx_snap_repo` on `architecture_snapshots(repository_id)`
  - `idx_nodes_snap`, `idx_nodes_key`, `idx_nodes_type` on `architecture_nodes`
  - `idx_edges_snap`, `idx_edges_source`, `idx_edges_target` on `architecture_edges`
  - `idx_city_repo` on `city_layouts(repository_id)`
  - `idx_endpoints_repo`, `idx_endpoints_key` on `code_endpoints`
  - `idx_paths_endpoint`, `idx_traces_endpoint` on execution paths and traces.

### 3.2 Migration `V2__multi_user_architecture.sql`
- Creates `app_users` table with UUID primary key, `supabase_user_id` unique index, email, and display name.
- Seeds the legacy system owner (`00000000-0000-0000-0000-000000000001`, `system@codecity.internal`).
- Adds `owner_id UUID` column to `repositories` with foreign key `fk_repo_owner` referencing `app_users(id) ON DELETE CASCADE`.
- Backfills all existing pre-migration repositories to the seed owner.
- Sets `owner_id` to `NOT NULL`.
- Replaces the global unique constraint `uq_repo_name` with a per-user composite unique constraint:
  ```sql
  ALTER TABLE repositories DROP CONSTRAINT IF EXISTS uq_repo_name;
  ALTER TABLE repositories ADD CONSTRAINT uq_user_repo_name UNIQUE (owner_id, repo_name);
  ```
  *Multi-Tenant Impact*: Two independent engineers (e.g. Alice and Bob) can each index `spring-projects/spring-petclinic` without name collision or data leakage.
- Creates `user_github_credentials` table with per-user encrypted Personal Access Token storage for private repo indexing.

## 4. Neon Serverless HikariCP Connection Tuning

Neon PostgreSQL operates in a serverless environment where compute endpoints suspend on idle. To prevent stale connections, socket timeouts, and connection pool exhaustion, `application.properties` was tuned:

```properties
# Neon PostgreSQL Connection Pool Tuning
spring.datasource.hikari.maximum-pool-size=10
spring.datasource.hikari.minimum-idle=2
spring.datasource.hikari.idle-timeout=30000
spring.datasource.hikari.max-lifetime=600000
spring.datasource.hikari.keepalive-time=30000
spring.datasource.hikari.connection-timeout=20000
spring.datasource.hikari.validation-timeout=3000
spring.datasource.hikari.connection-test-query=SELECT 1
```

- **Keepalive Interval (30s)**: Sends heartbeat TCP packets to keep the Neon compute endpoint awake during active sessions.
- **Max Lifetime (10m)**: Gracefully retires connections before Neon background proxies cycle connection state.
- **SSL Mode Require**: Enforces encrypted TLS 1.3 transit (`sslmode=require`).

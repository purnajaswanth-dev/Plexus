# CODECITY — DATABASE SCHEMA MISMATCH REPAIR REPORT
**Issue**: Column `repo_id` does not exist on table `repo_dependencies`  
**Classification**: Schema Naming Strategy & Flyway DDL Case-Sensitivity Alignment  
**Branch**: `feature/neon-supabase-multiuser`  
**Date**: November 2026  
**Status**: INVESTIGATED, REPAIRED, MIGRATED, & VERIFIED (Live Neon DB Verified, 79/79 Tests Passed)

---

## 1. Executive Summary

During repository indexing and reindexing operations, Spring Boot executed the following SQL to clear previous dependencies before inserting newly parsed packages:
```sql
DELETE FROM repo_dependencies WHERE repo_id = ?
```
PostgreSQL rejected this statement with:
```text
ERROR: column "repo_id" does not exist
Hint: Perhaps you meant to reference the column "repo_dependencies.repoId".
```

### The Root Cause
1. In `src/main/resources/db/migration/V1__initial_postgresql_schema.sql`, line 27, the foreign key column on `repo_dependencies` was created with explicit double quotes around mixed-case camelCase:
   ```sql
   CREATE TABLE IF NOT EXISTS repo_dependencies (
       id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
       "repoId" BIGINT NOT NULL,
       ...
       CONSTRAINT fk_repo_dependencies_repo FOREIGN KEY ("repoId") REFERENCES repositories(id) ON DELETE CASCADE
   );
   ```
2. In PostgreSQL, double-quoted identifiers preserve case (`"repoId"`). Unquoted identifiers in SQL (`repo_id`) do not match `"repoId"`.
3. In Spring Boot 3 / Hibernate 6, `SpringPhysicalNamingStrategy` is active by default. It maps camelCase logical names to snake_case physical column names.
4. In `RepoDependency.java`, `@JoinColumn(name = "repoId", nullable = false)` was specified. Hibernate converted this to the physical column name `repo_id`. When executing JPQL `DELETE FROM RepoDependency d WHERE d.repository.id = :repoId`, Hibernate sent `DELETE FROM repo_dependencies WHERE repo_id = ?`.
5. Because PostgreSQL stored `"repoId"`, the database rejected the query with a column-not-found error.

## 3. Safe Repair Implementation

In adherence to non-negotiable production safety rules:
- **No destruction**: Zero tables dropped, zero data truncated, zero database resets.
- **Forward-only migration**: Preserved existing applied Flyway migrations V1 and V2 to prevent checksum validation failures on existing databases.

### 3.1 Forward-Only Migration `V3__align_repo_dependencies_column_naming.sql`
Created `src/main/resources/db/migration/V3__align_repo_dependencies_column_naming.sql`:
```sql
-- ==============================================================================
-- CodeCity / Impact Mapper — Flyway Migration V3
-- Align repo_dependencies column naming with canonical snake_case standard
-- ==============================================================================

-- 1. Safely rename column "repoId" to repo_id if it exists with mixed-case
DO $$
BEGIN
    IF EXISTS (
        SELECT 1 
        FROM information_schema.columns 
        WHERE table_name = 'repo_dependencies' 
          AND column_name = 'repoId'
    ) THEN
        ALTER TABLE repo_dependencies RENAME COLUMN "repoId" TO repo_id;
    END IF;
END $$;

-- 2. Realign index to canonical snake_case naming
DROP INDEX IF EXISTS idx_repo_dep_repoid;
CREATE INDEX IF NOT EXISTS idx_repo_dep_repo_id ON repo_dependencies(repo_id);
```

### 3.2 JPA Entity Mapping Update
In `src/main/java/com/impactmapper/entity/RepoDependency.java`:
```java
// Updated from @JoinColumn(name = "repoId", nullable = false)
@ManyToOne(fetch = FetchType.LAZY)
@JoinColumn(name = "repo_id", nullable = false)
private Repository repository;
```
